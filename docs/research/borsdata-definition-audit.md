# Börsdata material-field definition audit

Audit date: 2026-11-04. Sources reviewed: Börsdata's public API wiki and OpenAPI schema, plus the existing Gränges reconciliation. This note records documentation findings; it does not define valuation policy.

## Documented by Börsdata

- The reports API exposes distinct `year`, `r12`, and `quarter` collections. The Reports wiki says R12 is calculated from the last four quarter reports; a quarter is normally three months. It labels quarter periods 1–4 and the full-year report 5, with half-year and broken-fiscal-year exceptions. Use endpoint family and `report_Start_Date` / `report_End_Date`, not `year` and `period` alone, to identify a fact's duration. The report-date fields are typed as dates in OpenAPI; the wiki calls `report_Date` “Report Date.” Neither source equates it with a PDF publication timestamp or states an as-of availability rule. [Reports: overview, periods, broken fiscal year, and data model](https://github.com/Borsdata-Sweden/API/wiki/Reports#overview-reports); [OpenAPI schema](https://apidoc.borsdata.se/swagger/v1/swagger.json), `ReportV1`.
- `original=1` requests values in the PDF report's original currency; `original=0` (the default) converts report data to the instrument's stock-price currency. The `currency` field remains the original report currency in either mode. `currency_Ratio` is described as the factor converting original report currency to stock-price currency. The Reports data-model table labels reported financial amounts “Million,” but also applies that label to EPS and dividend and contains duplicate/misaligned rows (including the price average/high/low translations). Treat this table as a field label/format aid, not a safe unit parser. OpenAPI types report values as doubles and metadata as name plus format; neither schema is an accounting definition or documents a universal magnitude for every field. Capture request mode and metadata version, then establish scale from issuer statements before normalization. [Reports: currency and data model](https://github.com/Borsdata-Sweden/API/wiki/Reports#report-currency); [OpenAPI](https://apidoc.borsdata.se/swagger/v1/swagger.json), `ReportV1`, `ReportMetadataV1`, `/v1/instruments/reports/metadata`.
- The report model lists `revenues`, `net_Sales`, `gross_Income`, `operating_Income`, `profit_Before_Tax`, `profit_To_Equity_Holders`, `earnings_Per_Share`, `number_Of_Shares`, `net_Debt`, CFO/CFI/CFF, `free_Cash_Flow`, and market-price summaries. The API documentation supplies field labels but no formula or policy for sales versus revenues, reported versus adjusted profit, attribution scope, EPS/share basis, lease treatment in `net_Debt`, cash-flow classifications, or `free_Cash_Flow`. Separate Börsdata knowledge-base pages provide some KPI definitions; their linkage to same-named report fields is not documented. A field name or matching value alone does not establish that linkage. [Reports: data model](https://github.com/Borsdata-Sweden/API/wiki/Reports#report-data-model); [OpenAPI `ReportV1`](https://apidoc.borsdata.se/swagger/v1/swagger.json).
- Börsdata's screener KPI page says screener values use the latest report and end-day price and have no history. Its list exposes market cap (ID 50, including SEK and USD variants), enterprise value (ID 49), net debt (ID 41/60), and Return on Invested Capital (ID 37), among other KPIs. These names and IDs identify the requested output, not the formulas, debt components, share universe, currency conversion date, or invested-capital convention. The documented metadata response supplies name/format and numeric/string flags only. [KPI Screener](https://github.com/Borsdata-Sweden/API/wiki/KPI-Screener); [KPI Screener List](https://github.com/Borsdata-Sweden/API/wiki/Kpi-Screener-List); [OpenAPI KPI metadata](https://apidoc.borsdata.se/swagger/v1/swagger.json), `KpiMetadataV1`.
- Historical KPI routes distinguish report basis (`year`, `r12`, `quarter`) and price type (`low`, `mean`, `high`). The history table lists multiples including P/E, P/S, EV/EBIT, EV/EBITDA, EV/S, P/FCF, and EV, but does not document the underlying numerator/denominator formula or how the price statistic is sampled within a period. [KPI History: report type, price type and table](https://github.com/Borsdata-Sweden/API/wiki/KPI-History#overview).

## Issuer-specific observations

The saved Gränges comparison found scoped matches between selected report rows and provider values for net sales/revenues, reported operating income, profit attributable to owners, statutory cash flows, and closing balance fields. It also found that EPS and shares did not consistently match the relevant issuer bases, the issuer's adjusted operating result was distinct from reported operating income in one period, and net-debt/FCF matches depended on issuer-specific definitions. These are observations for the documented Gränges periods only; they do not establish Börsdata-wide formulas. See [Gränges Börsdata mapping](../../examples/granges/docs/research/granges-borsdata-mapping.md), “Findings that affect valuation,” “Complete saved report-field map,” and “R12 and source-difference checks.”

## Börsdata knowledge-base formulas

These first-party definitions add formula context beyond the API wiki. They describe Börsdata's named KPIs; the API docs do not state that these formulas are the exact basis of similarly named report fields. Börsdata says it collects Nordic report data itself but sources global report data from Refinitiv and cannot adjust it, so uniform implementation across those source groups is also unverified. [Report data](https://borsdata.se/info/data/rapportdata).

- **ROIC:** Börsdata states `ROIC = Vinst / Investerad Kapital`, with `Investerad Kapital = Omsättningstillgångar - kortfristiga skulder - kassa + Anläggningstillgångar` (current assets minus current liabilities minus cash plus fixed assets). The numerator is only called “Vinst”; the page does not further specify its accounting line or adjustments. This is a profit-based numerator, distinct from its separate ROC page, which explicitly uses EBIT. Do not substitute operating NOPAT for Börsdata ROIC, or assume `net_Sales`/`net_Debt` API fields define the inputs, without confirming the API linkage. [ROIC (%)](https://borsdata.se/info/nyckeltal/roic); [ROC (%)](https://borsdata.se/info/nyckeltal/roc).
- **Net debt / indebtedness:** Börsdata describes `Nettoskuldsättningen = räntebärande skulder - kassa - kortsiktiga placeringar` (interest-bearing debt less cash and short-term investments). The linked `Nettoskuld (%)` KPI is this indebtedness divided by total assets. The page does not clarify whether leases are included in interest-bearing debt or prove the formula for report field `net_Debt`. [Nettoskuld (%)](https://borsdata.se/info/nyckeltal/nettoskuld).
- **Free cash flow:** Börsdata says FCF “consists primarily of cash flow from operating activities and cash flow from investing activities,” and that it is generally after tax. This is a qualitative description, not an equation or sign/classification rule; it does not establish `free_Cash_Flow = CFO + CFI` for every issuer. [FCF per share](https://borsdata.se/info/nyckeltal/fcf-aktie).
- **Enterprise value and market capitalization:** Börsdata defines `EV = Börsvärde + nettoskuldsättning` and `Börsvärde = Aktiekurs * Antal Aktier` (share price times number of shares). Its EV/EBIT page names EBIT as earnings before interest and taxes. The pages do not specify share class/count timing, exact net-debt field linkage, conversion/valuation timestamp, or whether the named API KPI IDs apply exactly this formula. [EV/E](https://borsdata.se/info/nyckeltal/ev-e); [EV/EBIT](https://borsdata.se/info/nyckeltal/ev-ebit).

## Unresolved for material use

Before using an API field in valuation, establish its linkage to the relevant knowledge-base formula and confirm from issuer reports and dated provider evidence: accounting line and consolidation/attribution scope; reported or adjusted basis; unit and currency mode; flow duration or balance-sheet date; and, for share measures, basic/diluted/issued/treasury basis. In particular, do not convert the qualitative FCF description into an equation, treat total investing cash flow as capex, assume API `net_Debt` includes/excludes leases, or use API `number_Of_Shares` as a current share count. Keep `report_Date`, issuer publication date, retrieval time, and report end date as separate timestamps until a primary source connects them. No API-to-knowledge-base field mapping or universal publication-lag rule was located in the sources reviewed.
