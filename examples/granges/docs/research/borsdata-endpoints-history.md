# Börsdata endpoint evidence

Historical case record from the earlier source layout. Original commands and source references describe the recorded checkpoint; use the [current example guide](../../README.md) for executable commands after the restructuring. Frozen evidence paths and source identities remain unchanged.

Research date: 2026-11-01. This is a factual endpoint reference plus explicitly labelled retrieval proposals for the Gränges walkthrough and a maintained Nordic watchlist. It is not a claim that every endpoint has been tested with this account.

## Source precedence and access

The public [Swagger UI](https://apidoc.borsdata.se/swagger/index.html) points to the [OpenAPI JSON](https://apidoc.borsdata.se/swagger/v1/swagger.json). Both were retrieved with local Python Requests on the research date, after the web reader could not open the UI. The JSON contains 33 paths; its fetched bytes had SHA-256 `88e267aaadd57f57fc1b44b6d8da8a4a1833511ee9f9ffd47ce783e202757260`. Paths, parameter names and response schemas below come from this schema unless another source is identified. The [saved schema](../../../../data/bf-borsdata-research/swagger.json) and [source record](../../../../data/bf-borsdata-research/swagger-source.json) preserve the inspected version.

Use `https://apiservice.borsdata.se` and the exact query parameter `authKey`. The [API repository README, “API KEY” and “Rate Limits”](https://github.com/Borsdata-Sweden/API#api-key) documents query authentication, 100 calls per 10 seconds, HTTP 429 with `Retry-After`, and a recommendation to remain below 10,000 daily calls. Its February 2025 membership notice supersedes older C# README wording about PRO access. Never store the credential-bearing URL in logs or evidence.

The [official C# sample, `ApiClient.cs`](https://github.com/Borsdata-Sweden/API-CSharp-Client/blob/master/Borsdata.Api.Dal/ApiClient.cs) is useful corroboration, not a complete production client: `GetReports` uses `maxYearCount` and `maxR12QCount`, while some comments retain older ten-report wording. `WebbCall` prints the URL including its authentication query; do not copy that logging behavior.

All paths below are GET requests relative to the base URL; omit `authKey` from stored request descriptions. `{id}` and `{insid}` both mean Börsdata instrument ID in their respective documented routes.

## Selected KPIs, not every screener permutation

Proposed starting historical valuation catalogue: P/E (2), P/S (3), P/B (4), EV/EBIT (10), EV/EBITDA (11), EV/S (15), and P/FCF (76). These IDs and annual/R12 mean/low/high variants appear in the [KPI History table](https://github.com/Borsdata-Sweden/API/wiki/KPI-History#kpi-table). Preserve all returned annual and R12 mean observations; add low/high for valuation range comparisons. This is a proposed selection, not evidence that each metric suits every issuer. Negative or missing denominators must not be silently interpreted as cheap valuation.

For operating quality, select margins, return on capital/equity, leverage, payout and growth metrics only after checking the live metadata and the applicable screener/history lists. Preserve the provider metric definition and compare it with report-derived calculations. Do not guess a KPI ID or assume every screener metric has history: the provider explicitly states historical coverage is a subset. [KPI History, Overview](https://github.com/Borsdata-Sweden/API/wiki/KPI-History#overview), [KPI Screener](https://github.com/Borsdata-Sweden/API/wiki/KPI-Screener).

## Interpretation constraints

1. **Currency mode belongs to each observation.** With `original=0`, amounts are converted to price currency, but the response `currency` remains the original reporting currency. Store request mode, original currency, price currency and the supplied ratio; do not infer amount currency from `currency` alone. Prefer `original=1` for report reconciliation. [Reports, Report Currency](https://github.com/Borsdata-Sweden/API/wiki/Reports#report-currency).
2. **Use actual dates and basis.** Quarter numbers are fiscal, not necessarily calendar quarters. Some issuers report only half-year periods. R12 is based on the last four quarters; never sum four balance-sheet stocks. The wiki's annual-series description also mentions a latest R12 row, so classify returned rows by dates/period and endpoint rather than assuming every annual response row is a completed fiscal year. [Reports, Overview and periods](https://github.com/Borsdata-Sweden/API/wiki/Reports#overview-reports).
3. **Units require verification.** The report wiki labels EPS and dividend “Million” and mismatches Swedish descriptions for average/high/low price. These are apparent documentation defects, not permission to multiply per-share values by one million. The separately acquired [live report metadata](../../../../data/borsdata/metadata/20261101T165621Z/reports.json) uses `CURR` for EPS/dividend, `MILL` for share count and `MCURR` for statement amounts. Preserve these codes; verify their canonical interpretation against source report units and numeric reconciliation. [Reports, Report Data Model](https://github.com/Borsdata-Sweden/API/wiki/Reports#report-data-model).
4. **Historical data can change.** The sample client's `GetStockSplits` comment says splits affect historical prices, report data and KPIs. Save versions and refresh affected series. Neither the consulted schema nor wiki establishes a point-in-time vintage API or guarantees that historical figures equal what investors saw then. A current historical series must not be labelled a historical information set. [C# ApiClient, GetStockSplits](https://github.com/Borsdata-Sweden/API-CSharp-Client/blob/master/Borsdata.Api.Dal/ApiClient.cs).
5. **Preserve missingness and per-instrument failure.** Batch responses can carry instrument errors; documented errors include `BAD_INPUT`, `NOT_EXIST`, and `NOT_ACTIVE`. HTTP 200 alone does not establish complete coverage. Several numeric schema properties are nullable, while others are non-nullable; neither fact justifies replacing null/missing data with zero. [Array errors](https://github.com/Borsdata-Sweden/API/wiki/API-Array-calls#instrument-error-message), [OpenAPI schemas](https://apidoc.borsdata.se/swagger/v1/swagger.json).
6. **Price and KPI timing is end-of-day.** The wiki says no intraday data and gives inconsistent update time wording: Home/KPI say around 20:00 UTC while Stockprice says 20:00 UTC+1. Check returned dates/update signals rather than treating one scheduled clock time as proof of freshness. [Home, Best practice](https://github.com/Borsdata-Sweden/API/wiki#best-practice), [KPI update timing](https://github.com/Borsdata-Sweden/API/wiki/KPI#when-is-kpis-updated), [Stockprice, EndDay](https://github.com/Borsdata-Sweden/API/wiki/Stockprice#endday).
7. **Catalogue identity is not company identity.** Instruments can be share classes, preferences or indices; classification relations can change. Keep instrument ID separate from issuer identity and preserve classification versions. [Instruments](https://github.com/Borsdata-Sweden/API/wiki/Instruments).

## Retrieval cadence proposal

For a maximum 100 instruments, two batches cover any endpoint whose documented limit is 50. Bootstrap full selected history, then refresh at most daily or manually as requested. Fetch latest prices, selected current KPIs and short-selling snapshots each refresh; re-fetch full statements and selected historical KPIs when evidence changes, after splits, and on a periodic reconciliation pass. Metadata can be checked weekly and when unknown IDs/fields appear. This schedule is a design recommendation; it has not been implemented.

Do not delete prior history simply because a rolling API window stops returning it. Deduplicate identical response bodies and observations; retain every changed version used in an analysis. Store the acquisition attempt even when the content is unchanged. For calendars and current snapshots, absence from a newer response is a status to investigate, not proof that an event never existed.

## Bounded conclusion and remaining verification

During this research, the parent agent separately acquired [Gränges KPI summary probes](../../../../data/borsdata/granges-research/20261101T165729Z/manifest.json). With `maxCount=20`, the annual response has 42 KPI groups with 15 rows each, including a 2026 period-3 observation above the 14 annual periods. With `maxCount=40`, the R12 response has 27 groups with 40 rows each. R12 summary does not include valuation IDs such as P/E (2) or EV/EBIT (10). Therefore retain the summary as a useful broad dataset, but do not label its 15 rows as 15 completed annual reports or treat it as complete historical valuation coverage. Its response schema does not carry a price basis, so explicit mean/low/high history requests remain the clear route for those comparisons.

The parent also acquired [live KPI metadata](../../../../data/borsdata/metadata/20261101T165621Z/kpis.json) and its [source manifest](../../../../data/borsdata/metadata/20261101T165621Z/manifest.json). An entry in its `kpiHistoryMetadatas` array is a catalogue entry, not proof that the historical endpoint supports that KPI; use the documented supported combinations and response evidence.

The docs support acquiring enough structured evidence for the proposed operating-company walkthrough: original financial statements, market history, selected historical/current KPIs, metadata and contextual events. They do not establish universal field equivalence to issuer reports, full website parity, complete buyback history, or point-in-time backtesting data.

Before expanding ingestion, verify live envelopes and actual coverage for the remaining datasets; reconcile material report fields against Gränges' PDFs; confirm split and financial restatement behavior on an affected example. This research worker made no authenticated calls or model runs; the parent agent's separately acquired metadata and summary probes are explicitly cited above. Those probes and the saved Gränges report snapshot do not test the other endpoints.
